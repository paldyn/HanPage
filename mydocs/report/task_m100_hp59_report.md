# Task #59 (M100) — 데스크톱 자동 업데이트 UX 개선 최종 보고서

- **이슈**: [paldyn/HanPage#59](https://github.com/paldyn/HanPage/issues/59) · 계획서 `plans/task_m100_hp59.md`
- **커밋**: `6aeee606`(구현) · `e532ac93`(버전 0.8.3) · **릴리스** `hanpage-desktop-v0.8.3`

## 1. 문제

작업지시자 보고: "팝업이 너무 투박하고, 업데이트할 때 로딩바나 아무것도 안 뜨고 몇 초 동안 가만히 있어서 버그 걸린 줄 알았다."

원인은 UI 미구현이 아니라 **순서**였다. `lib.rs` 가 `download_and_install(|_, _| {}, || {})` 를
사용자 승인 **뒤에** 호출해, 40MB 를 받는 동안 화면이 정지했다(진행률 콜백 2개 모두 no-op).
알림도 OS 네이티브 대화상자라 앱과 이질적이었다.

## 2. 해결 — 순서를 뒤집었다 (Claude 데스크톱 앱 방식)

| | 전 | 후 |
|---|---|---|
| 새 버전 발견 | 네이티브 모달로 작업 중단 | **조용히 백그라운드 다운로드**(무표시) |
| 알림 시점 | 받기 **전** | 받기 **끝난 뒤** |
| 알림 형태 | OS 대화상자 | 우상단 지속 토스트 + [지금 다시 시작][나중에] |
| 클릭 후 | 40MB 수신 동안 정지 | **즉시** 설치·재시작 |

기다림을 "표시"한 게 아니라 **없앴다** — 사용자가 누르는 시점엔 이미 받아둔 상태다.

## 3. 구현

**Rust** (`HanPage-Desktop/src-tauri/src/lib.rs`)
- `download()` 로 선다운로드 후 바이트를 전역 `READY_UPDATE` 에 보관, 완료 시 `hanpage://update-ready` emit
- 청크 단위 콜백을 누적해 `UpdateState` 유지(수동 확인 시 정확히 답하기 위함)
- 커맨드 3종: `cmd_update_status` / `cmd_update_check` / `cmd_update_apply`
- 네이티브 dialog 경로 제거, 메뉴 "업데이트 확인"은 웹뷰 토스트 흐름으로 위임

**프런트** (`rhwp-studio`)
- `core/desktop-bridge.ts`: 업데이트 API + 준비 완료 구독 (web-inert 유지 — 브라우저 영향 0)
- `ui/update-notice.ts`: 지속 토스트. '나중에' 를 눌러도 바이트를 버리지 않아 다음 클릭도 즉시 적용
- `ui/update-notice-text.ts`: 문구 생성 순수 함수 분리 + 단위 테스트 6건
- 웹뷰가 이벤트를 놓친 경우 대비해 초기화 시 상태를 직접 조회(펜딩 문서와 동일한 유실 방지 패턴)
