# Task #126 (M100) — Desktop 업데이트 준비 완료 작은 알림 수행계획서

- **이슈**: [paldyn/HanPage#126](https://github.com/paldyn/HanPage/issues/126)
- **브랜치**: `claude/desktop-update-ready-toast` (`origin/devel` `93b0a4a48` 분기)
- **작업지시자 보고(2026-10-08, Windows 0.8.10)**: "업데이트를 다받고난 후나 업데이트가 준비됬을때 알림창이 왜안뜨지?"
- **결정**: 같은 날 선택지 중 "작은 알림 1회 (추천)" 선택

## 1. 원인

| 경로 | 동작 | 판정 |
|---|---|---|
| 백그라운드 확인 → 다운로드 | 상태 표시줄 진입점(`#desktop-update-entry`)에 진행률 표시 | 정상 |
| 다운로드 완료(`ready`) | `receiveStatus`가 진입점 문구만 바꾸고 카드는 열지 않음(0.8.9 편집 흐름 보호 규칙) | **안내 부족** — 상태 표시줄을 보지 않으면 모름 |
| 사용자가 연 카드 | 저장 확인 → 적용 | 정상 |

0.8.9에서 큰 카드의 자동 표시를 없앤 규칙은 유지해야 한다(편집 중 포커스 탈취 방지). 준비 완료만
눈에 띄되 흐름을 끊지 않는 별도 표면이 필요하다.

## 2. 범위

1. `ready` 진입 시 오른쪽 아래(상태 표시줄 위)에 "새 버전 X 준비됨" 작은 알림을 **버전당 1회** 띄운다.
2. 포커스를 가져가지 않는다. 버튼 클릭은 mousedown 기본 동작을 막고, 키보드로 들어온 경우에만 닫을 때
   들어오기 직전 위치로 되돌린다. 모달이 열려 있으면 편집기로 포커스를 보내지 않는다.
3. 8초 뒤 자동으로 닫는다. 실제 마우스 이동으로 올려 두었거나 포커스가 안에 있으면 유지한다. Esc로 닫는다.
4. [업데이트]는 기존 카드와 저장 확인·적용 흐름을 시작하고, [나중에]는 알림만 닫는다.
5. 모달이 열려 있으면 닫힐 때까지 미룬다. 카드를 이미 본 버전·적용 중에는 띄우지 않는다.
   쌓임 순서는 팝오버(9000)·모달(10000)보다 아래(8900)로 둔다.
6. (2차 검토 반영) 앱 창이 뒤에 있으면(다른 앱 사용·최소화) 알림을 미루고, 떠 있던 알림은 창을 떠난 동안 자동 닫힘을
   멈춘다. 쌓임 순서는 사용자가 연 모든 팝업(메뉴·양식 목록·비교 창 포함)보다 아래(z-index 10)로 낮춘다. 모달 안에서
   키보드로 들어온 알림을 닫으면 그 모달 안의 원래 위치로 포커스를 되돌린다.

비범위: tauri-plugin-updater 다운로드·설치, 확인 주기, OS 알림 센터, 웹 빌드(업데이트 기능 없음).
